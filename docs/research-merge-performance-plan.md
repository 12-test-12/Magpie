# 研究写入冲突与查询优化方案

日期：2026-10-24。基线：`8a7feb9`，0.31.0 / schema v20。

用户授权按项目复查建议推进。本批先处理冲突草稿、持续浏览器回归和笔记查询开销；先写本文，再修改业务代码。搜索扩展、JS 深化、Finding 三维状态、报告扩展和所有 Agent / 主动测试继续后置。

## 1. 冲突后的字段核对

- Note 正文、归档状态、证据关联，以及实体人工名称/审核状态，均以“原读取值 / 最新值 / 我的草稿”逐字段核对。取消只替换版本号后整份重提旧草稿的入口。
- 草稿未改的字段默认保留最新值；仅草稿改动的字段默认保留草稿；两边改成相同值视为一致。两边对同字段作不同修改时，必须明确选择最新值或草稿，未选齐不能继续保存。
- 获取最新值、应用选择均只更新本地草稿，不自动提交写请求；应用时采用被核对记录的版本，后续再发生并发更新仍由服务端 409 拒绝。正文、归档、关联证据都纳入核对，不能只保护正文。
- 失败保留草稿；项目/对象切换和组件卸载继续取消读取并忽略迟到响应。最新记录失效时不能保存。服务端版本/理由/项目检查、历史与审计保持原契约。
- 本批不改 Task / Finding 的状态模型或写入契约，不改原文、Evidence、Contribution、身份、归一化及 Undo/Redo。

## 2. 笔记列表查询

- 复查中 50 条无附加证据笔记执行 202 次 SELECT。保留现有筛选、游标签名、排序、总数、脱敏与响应字段，改用当前页 ID 的批量详情读取和证据 JOIN，消除逐条详情查询。
- 详情和列表共用组装逻辑；项目约束、原始证据、当前修订、归档、失效状态及研究证据都必须一致。绑定参数，不生成用户 SQL；一页上限仍为 100。
- 加入查询数量预算与列表/详情等价回归，并在合成数据中记录前后查询数、响应字节与耗时。顺便测量现有十万接口组合筛选，不因局部优化宣称严格性能契约通过。
- 不新增持久化缓存、事实副本、索引或 schema 迁移；本批不重构全局分页/计数、API JSON 筛选或报告装配。

## 3. 持续浏览器回归

- 扩展既有 `scripts/ci/browser.py` 的唯一合成工作区，在原 API 场景之后执行独立研究资料场景。仅测试台架访问合成数据库，拒绝覆盖已有库。
- 真实页面覆盖：两窗口笔记冲突与逐字段选择、新增证据/归档保留、再次并发更新仍拒绝、任务证据关联、人工字段冲突、裸 JS 文件导入与来源回查、增量 Undo/Redo、空项目隔离。
- 同时检查 dev.py 页面和后端正式静态页面、1440px / 1000px 布局、页面异常与外部请求；失败必须保留脱敏诊断并令 CI 失败。令牌日志仍放私有本地目录，不上传。

## 4. 验证与交付

- 运行定向及完整后端 `check.py`、前端完整测试、正式构建、工程/契约检查和源文件空白检查；不放宽现有红线。
- 按 computer-use 技能验证本地真实浏览器，使用 dev.py 的新命名合成工作区，不操作真实项目。Python 3.13 不可用时如实登记实际解释器。
- HTTP/CLI 响应形状与 schema 均保持不变，应用继续 0.31.0/schema v20；内部重构和 UI 修复不新增对外契约版本。
- 同步路线、主线二验收记录及本批实际验证记录；本地提交，不推送、不合并、不打包、不发布。用户未跟踪的 Agent 方案原样保留。
