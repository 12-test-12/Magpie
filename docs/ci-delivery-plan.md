# Magpie 工程流水线改造方案

日期：2026-10-20。基线：`10648bc`，应用 0.30.0 / schema v19。独立分支：`codex/ci-delivery-pipeline`。

## 1. 参考与适配范围

用户要求参考 [BobcGn/final 的 GitHub Actions 流水线](https://github.com/BobcGn/final/blob/main/.github/workflows/ci.yml)，制作适用于 Magpie 当前要求的工程流水线。已读取参考文件，内容 blob 为 `aa901a9a0e4e895318131d7247581eb454b4d66f`。借鉴事实源检查、分模块测试、最小权限、并发取消、制品留存和 PR 协作；不引入其硬件、Go、MQTT、Android、微信或 Multica 业务。

本批是工程 CI/CD，不改应用内数据导入管线，也不开发 Agent 或扫描执行器。先完成本文，再实施；保持已有解析/证据/Contribution/Undo/Redo 契约、历史记录和未跟踪的 Agent 方案。基线包含用户已有合并，不重写历史。本批不合并、不推送、不创建远程 PR、不实际发布或更改 GitHub 设置。

## 2. 当前缺口与目标

当前 `.github/workflows/ci.yml` 在 PR/main/tag 上测试并打包，main 成功后删除并重建 edge 预发布。本批将日常验证与手动交付拆开，避免开发推送自动改写发布资源。应用版本/API/schema 不变。

| 层次 | 本批交付 |
|---|---|
| Contracts | 工程事实文件、版本一致性、迁移连续性、OpenAPI 快照版本/结构、工作流 YAML/Actions 语法、变更空白检查 |
| Backend | Linux/Windows Python 3.13 完整 `check.py`；Linux Python 3.11 验证声明下限；保留 11 条静态红线、全部现有测试及六组设计验收 |
| Frontend | 固定 Node 22.19.0，npm ci、前端完整测试、构建；同时检查已跟踪差异和未跟踪产物，确保正式资源入库且可重建 |
| Browser | 可重复的本地/CI 同入口合成验收，通过 dev.py 独立命名工作区检查 API 研究筛选、样本对照、证据、空项目、窄桌面和生产静态页面，禁止真实项目与外部目标 |
| Required Checks | 无论上游失败/取消均运行统一汇总；缺失或跳过必要任务不能算成功，提供稳定的分支保护检查名 |
| 手动交付 | 从同仓库 main 的成功 CI 运行固定到完整 commit SHA；显式确认对应本地浏览器验收和记录路径后，才允许双平台打包与解压后冒烟 |
| 制品与发布 | 输出版本/SHA/平台/大小/SHA-256 清单，保存制品；默认只交付 artifacts，可另选生成草稿 Release，不自动发布、不删除 edge、不覆盖已有标签或 Release |
| 协作 | PR 模板、真实仓库所有者的 CODEOWNERS、分支保护/发布环境配置指南；不照搬多人团队强制规则导致个人项目无法推进 |

## 3. 执行与权限边界

- CI 触发：所有分支的 push、指向 main 的 PR、merge_group 和手动运行；开发分支可直接试跑，不需要先合并；不使用路径条件导致必要检查无结果。
- 默认 `contents: read`，checkout 不保留凭据，PR 不运行任何持有写令牌的发布任务；不用 pull_request_target 或从 PR 制品提权发布。
- 仅手动交付最后的草稿发布任务使用 `contents: write`，固定 source SHA；输入经环境变量传递和显式校验，避免拼进 shell 代码。
- 发布 job 引用 `release` 环境。环境/分支保护是 GitHub 服务端配置，仓库文件不能证明已启用；实施记录须区分已实现与待远程启用。
- 本地验收确认是操作者声明，自动门禁只核对声明、来源 SHA、成功 CI、main 归属与验收文件存在，不冒称机器能判断截图或人工结论真实性。
- 打包继续复用现有 PyInstaller spec 和解压后 smoke.sh；构建期依赖下载与应用运行时零出站分开。
- 严格计时性能契约继续在固定本地环境执行，不把共享 runner 计时作为放行依据。
- 覆盖率先记录真实 pytest 覆盖范围并上传报告，不照搬参考项目 80%/90% 阈值；有基线后另行制定，避免虚报或通过删测试达标。

## 4. 文件与验证

修改限定在 `.github/`、`scripts/ci/`、打包说明及工程文档；业务代码、旧迁移和原始数据不改。浏览器工具采用 CI 临时目录安装，本地复用已有工具，应用和前端依赖/锁文件保持不变。新增构建清单/交付门禁的测试须覆盖正常、失败、来源不一致及篡改情况。

本地验证：事实源/工作流检查、actionlint、交付门禁与制品校验回归、前端测试及构建重现检查、通过 dev.py 的真实浏览器合成验收；能执行的环境据实记录。优先 Python 3.13，不可用则使用本机 3.12.4 并声明未验证的平台。不会把本地 YAML 检查写成 GitHub Actions 已跑通，也不会在浏览器验收前实际打包发布。
