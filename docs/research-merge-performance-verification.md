## 已实现

1. 笔记正文、归档、关联研究证据，以及实体人工名称和审核状态，提供原读取值、最新值、草稿的逐字段核对。未改字段采用最新值，仅草稿改动的字段采用草稿；双方改成不同值时必须明确选择。应用选择不发写请求，仍需人工保存；版本检查不绕过，再次并发更新仍返回 409。
2. 获取最新值失败、取消核对或再次冲突均保留草稿。核对时禁用编辑，项目/对象切换取消读取并忽略迟到响应。修订、证据与理由继续沿原有服务端原子写入、历史和审计，不覆盖原始事实。
3. 笔记列表按当前页 ID 批量查询详情和证据，列表/单项详情共用组装；筛选、排序、游标签名、总数、脱敏及返回字段保持不变。无新缓存、索引或迁移。
4. CI 浏览器回归新增研究资料合成项目，扩展到两窗口笔记/人工字段冲突、任务证据持久化、裸 JS 文件导入和受管来源、增量 Undo/Redo、正式静态页面和空项目隔离。浏览器超时上限调整为 300 秒；任何子场景失败仍令 Browser/Required Checks 失败。

另将既有 `.magpie-dev/mainline-two/` **合成**库以只读连接 backup 到内存，仅在副本迁移。项目有 100,000 个 Endpoint，**没有 HTTP 请求样本**：

- API 主机分组重复 3 次中位 **167.172 ms**，100 组、当前页 50 组，响应 **4,175 字节**。
- 参数 redirect/query + 状态 200 + Cookie 的组合筛选在 COUNT 阶段超过 **15 秒**，用 SQLite progress handler 中断，实际 15,000.058 ms；不能据此宣称查询成功、返回 0 或大数据性能达标。
- 早期无中断预算的测量停留在该 COUNT；随后改成有界测量并保留失败过程。结果 `_scratch/merge-performance-probe.json`。后续应独立优化 API 组合筛选的相关子查询/查询计划，并补含真实合成请求样本的分布、HTTP 和并发测量。本次没有顺手更改其语义或索引。
