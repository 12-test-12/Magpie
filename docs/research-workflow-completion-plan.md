# 现有研究能力完善方案

日期：2026-10-21。基线：`82c17a4`，0.30.0 / schema v19。

用户要求完善项目核查表的前三项并交付本地。Agent 无限期后置；本批不实现任何 Agent、主动测试或网络取数。先完成本文，再修改业务代码。交付为独立本地分支和 Git 提交，远程推送仍由用户执行。

## 1. JS 本地接入与可解释分析

- 导入对话框提供裸 JS 内容/本地文件与显式绝对资源 URL 的关联，生成标准 `magpie_js` manifest，经原生解析器和既有导入队列处理；保留原始 JS 文件的哈希、名称和内容，不从脚本地址推断运行基址。
- 支持不依赖执行的静态字符串拼接调用候选；动态变量、作用域和未知语法继续报告不确定，不冒充完整 AST 或请求事实。规则版本显式更新，不改旧记录。
- 展示 JS URL/域名和敏感串候选的脱敏定位；复用现有敏感串规则，只保存脱敏候选及哈希/偏移，不能将候选当作已确认泄露。
- 完整 AST、跨作用域变量传播和 SourceMap 原始源码映射不以小规则冒充实现；本轮先把本地文件、候选和证据回查形成完整可用路径，保留明确的能力说明。

## 2. Notes 与任务资料关联

- 笔记继续由既有 `ops.add_finding` 生成 Observation / Evidence / Contribution，不建第二份笔记事实。新增人工工作层保存编辑版本、归档状态与项目内 Evidence 引用；原始文本、原文证据与贡献不修改。
- 编辑须携带读取时版本；旧窗口返回 409，保留草稿并要求显式重载。每次编辑/归档追加历史与审计，可查看原始文本和历史版本，不提供永久删除。
- 搜索、列表与报告读取当前人工修订，归档笔记默认不列入活动列表；仍可显式查询归档。导入撤销后不伪造有效笔记，不删除修订历史；Redo 恢复同一笔记及其修订。
- 任务新增项目内 Evidence 关联；对象详情和证据详情均可创建待办并回查相关任务/笔记。保留旧实体关联，新增证据关联不重解释旧数据。
- 新增原子迁移 020，不修改 001–019。新表仅保存人工工作记录和现有 ID 引用。GC 必须保留这些引用，跨项目引用和外层事务回滚均需验证。

## 3. 增量变化与旧接口

- `/search` 与 CLI search 复用现有工作区字面检索，明确不是 DSL；同步 MCP 能力说明，保持原有信封/退出码。
- `/diff` 复用 CLI 已有有效贡献与作业归属口径，提供有界分页和变化总数；增加工作台入口，可回查对象，Undo/Redo 后跟随有效贡献变化，不将累计计数称为新增。
- `/paste` 仅把有界文本保存为受管输入，再走既有导入服务；显式文件名/解析器、预览与归档选项，不另建写事实通道。
- 实体名称/审核字段的人工赋值通过 `ManualWriter`，显式版本与理由保护，不直接更新事实缓存、不覆写原生观测。界面显示原值/人工值及来源。

- 运行后端 `check.py`、前端完整测试、正式构建、OpenAPI 契约和源文件空白检查。首选 Python 3.13；不可用时记录实际解释器。
